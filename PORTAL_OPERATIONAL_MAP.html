#01 Anonymous Auth Permits Full Database Exfiltration
CRITICAL
📁 firestore.rules:L8-10, L105, L128

The Bug: isAuthenticated() checks only request.auth != null. Because anonymous auth is enabled for public joiners, any anonymous session satisfies authentication.

Impact: Any visitor can query and scrape candidate PII, phone numbers, and Aadhaar numbers from Firestore.

Fix Blueprint: Add request.auth.token.firebase.sign_in_provider != 'anonymous' to all authenticated read rules.
#02 Plaintext Password Storage in Firestore Documents
CRITICAL
📁 employeeService.ts:L793, L1511 & bulkImportUtils.ts:L830

The Bug: Generated employee passwords (mockPassword) are written directly into Firestore documents under password or initialPassword.

Impact: Plaintext credential exposure for all employees, violating basic security standards.

Fix Blueprint: Cease writing plaintext passwords to Firestore; manage credentials exclusively via Firebase Authentication.
#45 Terminated Employees Retain Permanent SSO Login via Google Auth
CRITICAL
📁 functions/index.js:L330-415 (employeeGoogleLogin)

The Bug: In employeeGoogleLogin, the Cloud Function mints custom tokens by resolving Google UID/email with ZERO checks for isActive === false or isRelieved === true.

Impact: Relieved or terminated employees can log in indefinitely via "Sign in with Google" and view internal communications.

Fix Blueprint: Reject authentication with permission-denied if isActive === false or isRelieved === true on employee and submission records.
#46 Onboarding Employees Bypass Inactive/Relieved Account Lockout
CRITICAL
📁 functions/index.js:L465-495 (employeeLogin)

The Bug: employeeLogin checks onboarding_submissions first where status == 'Approved'. Step 1 omits checks for isActive === false or isRelieved === true.

Impact: Terminated employees whose record matches in onboarding_submissions bypass account deactivation completely.

Fix Blueprint: Check subData.isActive === false || subData.isRelieved === true in Step 1 of employeeLogin.
#48 Privilege Escalation & Arbitrary Password Reset in Employee Auth
CRITICAL
📁 functions/index.js:L1200-1235 (adminControlEmployeeAuth)

The Bug: adminControlEmployeeAuth checks only if the caller exists in staff_accounts. It never verifies role permissions or SuperAdmin status.

Impact: Any low-privilege field staff can reset passwords or unlink auth for any employee or manager.

Fix Blueprint: Require isSuperAdmin() or EMPLOYEES_MANAGE permission before executing resets.
#50 Missing Composite Index Causing Attendance Calendar Crash
HIGH
📁 src/services/engagementService.ts:L130-145

The Bug: Mixing equality on userId with range comparison on date requires a composite index on attendance (userId ASC, date ASC), which is missing.

Impact: Monthly attendance queries fail silently and return empty arrays.

Fix Blueprint: Add composite index attendance (userId ASC, date ASC) to firestore.indexes.json.
#51 Unhandled Crash on Relieving or Rejoining Approved Onboarding Staff
HIGH
📁 src/services/employeeService.ts:L2280-2365

The Bug: relieveEmployee calls doc(db, 'employees', employeeId) directly. Self-onboarded staff doc IDs match their submission ID (e.g. UDF-202609-1R6W), not EMP-xxxxx.

Impact: updateDoc crashes with No document to update, breaking resignation approvals and re-hiring.

Fix Blueprint: Add fallback query: if !empSnap.exists(), query where('employeeId', '==', employeeId).
#53 Phantom Account Updates (Approved Changes Never Committed)
HIGH
📁 App.tsx:L1313-1325 (handleAdminAccountUpdateAction)

The Bug: Approval handler marks requests approved and sends notifications, but contains // For now, let's skip auto-update of fields.

Impact: Bank account, phone, and address changes are never applied to employee records.

Fix Blueprint: Commit requested changes directly to employees and onboarding_submissions upon approval.
#54 Non-Atomic Leave Deductions & Permanent Leave Quota Loss
HIGH
📁 src/services/employeeService.ts:L1830 & App.tsx:L1145

The Bug: Balance deduction uses client-side read-modify-write. Reverting or deleting approved leaves never refunds days.

Impact: Race conditions on concurrent approvals; permanent loss of employee leave days upon cancellation.

Fix Blueprint: Use Firestore increment(-days) on approval and increment(+days) on revert/delete.
#55 Premature Workflow Termination by SuperAdmin Reviews
MEDIUM
📁 App.tsx:L1125, L1205, L1285

The Bug: Level progression evaluates if (nextRawLevel <= maxLevels && !isSuperAdmin). For SuperAdmins, it immediately jumps to final approval.

Impact: SuperAdmin reviewing Level 1 prematurely marks multi-tier requests fully approved, skipping Level 2 & 3 reviews.

Fix Blueprint: Advance levels normally unless an explicit "Force Final Bypass" action was selected.
