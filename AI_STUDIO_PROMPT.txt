### 2. Core Architecture
The app is a Single Page Application (SPA) where `App.tsx` handles the primary routing based on User Roles (Admin vs Employee).

**Services Layer (`src/services/`)**:
- `authService.ts`: Handles Login/Logout using Firebase Auth. Resolves user roles from Firestore `staff` collection.
- `employeeService.ts`: Manages employee onboarding submissions (`submissions` collection) and profiles (`employees` collection).
- `leaveService.ts`: Manages leave requests (`leaveRequests` collection).
- `staffService.ts`: Connects to Cloud Functions to allow Admins to create new Staff accounts programmatically.
- `storageService.ts`: Handles file uploads (employee docs, attachments) to Firebase Storage.

### 3. Key Features Implemented
- **Authentication**: Email/Password login. Admins and Field Officers have different permissions.
- **Role-Based Access Control (RBAC)**:
  - **Super Admin**: Full access.
  - **HR Manager**: Can manage submissions, leaves, and staff.
  - **Field Officer**: Limited access (View only or specific tasks).
- **Employee Onboarding**:
  - Complex multi-step form for new joiners.
  - Multi-level approval workflow (Level 1 Supervisor -> Level 2 HR).
  - Generates an Employee ID upon final approval.
- **Leave Management**: Employees request leave; Managers approve/reject.
- **Admin Dashboard**: Statistics, recent submissions, audit logs.

### 4. Database Structure (Firestore)
- **`staff`**: Admin user profiles ({ username, roleId, email, isDisabled }).
- **`employees`**: Active employee profiles.
- **`submissions`**: Pending onboarding forms with status tracking.
- **`leaveRequests`**: Leave history.
- **`roles`**: Configurable roles and permissions.

### 5. Deployment
- The app is configured for deployment on **Vercel** or **Netlify**.
